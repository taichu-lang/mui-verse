# Table

分页表格。基于 `TableContextProvider` 管理**分页状态 + 数据拉取 + loading 态**，桌面端渲染标准表格、移动端自动切换到卡片式布局（同一份 `columns` 配置，无需重写）。搭配 `TablePagination` 完成"表格 + 翻页器"的常见组合。

- `TableContextProvider`：外层容器，持有 `page` / `pages` / `rows` / `loading` 状态并暴露给内部子组件。
- `Table` / `TableDesktop` / `TableMobile`：容器内部自动根据 `useMobile()` 选择渲染分支，通常不需要直接引用。
- `TablePagination`：读取 context 里的 `page` 与 `pages`，渲染 MUI 分页器并回写 `page`。
- `useTableContext`：在 `TableContextProvider` 内的子组件中读取当前分页状态，用于自定义摘要、导出按钮等。

## 引入

```tsx
import {
  TableContextProvider,
  TablePagination,
  type TableColumn,
  type TableContextHandle,
} from "@mui-verse/ui/components/data";
```

## 基础用法

```tsx
type Usage = {
  id: string;
  created_at: string;
  amount: number;
};

const columns: TableColumn<Usage>[] = [
  {
    header: <span className="font-medium">Date</span>,
    render: (row) => stringifyDate(row.created_at),
  },
  {
    header: <span className="font-medium">Amount</span>,
    render: (row) => row.amount,
    align: "right",
  },
];

<TableContextProvider<Usage>
  columns={columns}
  fetch={(page, limit, signal) => getUsages(page, limit, signal)}
  stickyHeader
  className="gap-4"
>
  <TablePagination placement="center" shape="rounded" />
</TableContextProvider>;
```

行为：

- 组件挂载时自动以 `page=1` 拉一次数据；
- 用户点击 `TablePagination` 翻页 → `page` 更新 → `useEffect` 重新触发 `fetch`；
- **翻页时组件自动 abort 上一次未完成的请求**，保证旧响应不会覆盖新数据；
- 拉取期间桌面端在表格 body 显示居中的 `AnimatedSpinner`；移动端在卡片位置显示 spinner。

## 数据契约：`PaginationData<T>`

`fetch` 必须返回 `PaginationData<T>`：

```ts
interface PaginationData<T> {
  items: T[];
  total: number;   // 总条数（不是总页数）
  page: number;
  limit: number;
}
```

- 组件用 `Math.ceil(total / rowsPerPage)` 算出总页数并传给 `TablePagination`；
- `page` 与 `limit` 会被组件自身状态覆盖，可以原样回传后端返回的值，不影响翻页逻辑。

## `TableColumn<T>`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `header` | `ReactNode` | 表头内容，可任意 JSX（图标、粗体、tooltip 等） |
| `render` | `(row: T) => ReactNode` | 单元格渲染函数；接收整行数据 |
| `align` | `"left" \| "right" \| "center"` | 单元格对齐；默认 `left`。桌面端作用于 `<TableCell>` 的 `align`，移动端右侧值区域固定右对齐（`align` 主要影响 header 的呈现） |
| `width` | `number \| string` | 桌面端 `<TableCell>` 的 `width`，移动端忽略 |

> `T` 必须满足 `{ id: string | number }`（`IdOriented`）——`id` 用作行的 React `key`。若原始数据没有 id，请在 `fetch` 里补一个稳定的字段（业务主键 / 后端 uid），不要用数组下标。

## `TableContextProvider` Props

| 属性 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `columns` | `TableColumn<T>[]` | — | 列配置，必填 |
| `fetch` | `(page, limit, signal) => Promise<PaginationData<T>>` | — | 数据拉取函数，必填。`signal` 是 `AbortSignal`，翻页或 `reload` 时上一次请求会被 abort |
| `rowsPerPage` | `number` | `10` | 每页条数，同时作为 `fetch` 的 `limit` 参数传入 |
| `stickyHeader` | `boolean` | `false` | 桌面端表头是否 sticky；配合外层限高容器使用 |
| `emptyState` | `ReactNode` | — | 空态占位（`rows.items.length === 0` 且 `loading=false` 时展示） |
| `className` | `string` | — | 附加在包裹表格 + `children` 的外层 `<div>` 上（该 div 默认 `flex w-full flex-col`） |
| `ctrlRef` | `Ref<TableContextHandle>` | — | 命令式句柄，暴露 `reload()` 方法 |
| `children` | `ReactNode` | — | 通常是 `<TablePagination />`，也可以是自定义摘要 / 导出按钮 |

## 分页器 `TablePagination`

`TablePagination` 必须作为 `TableContextProvider` 的子节点使用，它读取 context 里的 `page` / `pages` 并触发 `setPage`：

| 属性 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `color` | `"standard" \| "primary" \| "secondary" \| "error"` | `"standard"` | 传 `"error"` 时会覆盖为 `error.400` 系配色 |
| `shape` | `"rounded" \| "circular"` | `"circular"` | 按钮形状 |
| `placement` | `"start" \| "center" \| "end"` | `"end"` | 分页器在其父容器内的水平位置 |
| `className` | `string` | — | 附加到外层 `<div>` 上 |

```tsx
<TableContextProvider {...}>
  <TablePagination placement="center" shape="rounded" />
</TableContextProvider>
```

也可以直接使用底层的 `Pagination`（`@mui/material/Pagination` 的薄封装，仅补充了 `error` 配色）——适合脱离 `TableContext`、只需要一个分页器的场景。

## 命令式刷新 `ctrlRef`

在"新增一条数据后想刷新表格"这类场景，通过 `ctrlRef` 触发 `reload`：

```tsx
import { useRef } from "react";
import type { TableContextHandle } from "@mui-verse/ui/components/data";

const tableRef = useRef<TableContextHandle>(null);

const handleCreate = async () => {
  await createUsage(payload);
  tableRef.current?.reload();
};

<TableContextProvider<Usage>
  ctrlRef={tableRef}
  columns={columns}
  fetch={fetchUsages}
>
  <TablePagination />
</TableContextProvider>;
```

`reload()` 的行为：

- 当前不在第 1 页 → `setPage(1)`，`useEffect` 触发重新拉取；
- 当前已经在第 1 页 → 直接重新调用 `fetch(1, rowsPerPage)`。

> `ctrlRef` 是普通 prop——按项目约定不要用 `React.forwardRef` 包裹。

## 在自定义子组件里读取分页状态

`useTableContext()` 可以在 `TableContextProvider` 内的任意后代里读取：

```tsx
import { useTableContext } from "@mui-verse/ui/components/data";

function TableSummary() {
  const { page, pages, rows, loading } = useTableContext();

  if (loading) return null;

  return (
    <div className="text-text-secondary text-sm">
      第 {page} / {pages} 页，共 {rows.total} 条
    </div>
  );
}

<TableContextProvider {...}>
  <TableSummary />
  <TablePagination />
</TableContextProvider>;
```

context value：

```ts
{
  page: number;
  pages: number;
  loading: boolean;
  rows: PaginationData<IdOriented>;
  setPage: (page: number) => void;
  setLoading: (loading: boolean) => void;
}
```

在 provider 外调用 `useTableContext()` 会抛错。

## 响应式：桌面 / 移动端

`Table` 内部通过 `useMobile()` 判断，自动切换渲染分支：

- **桌面端** (`TableDesktop`)：基于 MUI `<Table>` 渲染完整表格；偶数行有 `grey.100` 底色，表头带主题色背景；`stickyHeader` 生效。
- **移动端** (`TableMobile`)：每行数据渲染为一个 `<Paper>` 卡片，内部按 `header ↔ 值` 上下叠加；`align` / `width` / `stickyHeader` 不生效，`emptyState` 仍然可用。

**同一份 `columns` 配置在两端都要能渲染**——`render(row)` 返回的内容应该是无关容器宽度的（数值、日期、tag 等）。避免在 `render` 中依赖桌面表格的横向布局。

## 竞态取消

`TableContextProvider` 内置 `AbortController`，保证翻页、`reload()`、或 unmount 时自动 abort 上一次 in-flight 请求，旧响应**不会覆盖**新数据。组件做了两层防御：

1. **`signal` 传给业务方**：如果 `fetch` 内部将 `signal` 透传给 `fetch()` / `axios()` 等，请求会在网络层真正取消，节省带宽。
2. **`signal.aborted` 兜底**：即使业务方忽略了 `signal`，组件在 await 之后会检查 `signal.aborted`，拒绝 `setRowsState`——旧数据到达也不会写入。

```tsx
// 推荐：透传 signal
const fetchUsages = useCallback(
  async (page: number, limit: number, signal: AbortSignal) => {
    const res = await fetch(`/api/usages?page=${page}&limit=${limit}`, { signal });
    return res.json();
  },
  [],
);

// 也OK：忽略 signal（旧请求继续跑完但结果被组件丢弃）
const fetchUsages = useCallback(
  async (page: number, limit: number, _signal: AbortSignal) => {
    return await legacyApi.getUsages(page, limit);
  },
  [],
);
```

> `fetch` 抛出 `AbortError` 时组件会静默吞掉（因为 `signal.aborted` 为 `true`，直接 return）；非 abort 导致的错误仍会抛出。错误 toast / retry 请在业务侧的 `fetch` 内部处理。

## 常见注意点

- **`fetch` 用 `useCallback` 包一层**：`TableContextProvider` 的 `useEffect` 依赖 `fetch`，每次父组件重渲染都传入新的 `fetch` 引用会造成无限拉取。
- **`stickyHeader` 需要限高容器**：`sticky` 生效前提是外部有可滚动的父容器；直接放在页面里不会 sticky。
- **`emptyState` 在 loading 期间不显示**：只在 `loading=false && rows.items.length === 0` 时才渲染，避免"首帧空态一闪"。
- **`id` 必须稳定**：作为 React `key`；不稳定会导致翻页时行组件被销毁重建，破坏内部状态。
- **`rowsPerPage` 变更不会自动回到第 1 页**：如果暴露给用户切换 pageSize，请在切换后自行 `setPage(1)` 或调用 `reload()`。
