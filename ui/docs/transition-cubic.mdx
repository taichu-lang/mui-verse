# transition-cubic

统一的 hover/state 过渡工具类，提供 0.5s `cubic-bezier(0.65, 0, 0.35, 1)` 的"出入对称"动效，并内置**圆形扩散背景**（从中心向四周渲染，离开时反向收拢）。

## 核心设计决策

### 为什么不只用 Tailwind 的 `transition-*`？

Tailwind 默认的 `transition` 时长是 150ms、缓动是 `ease`，节奏偏快、曲线偏平直，难以营造"质感"。`transition-cubic` 用一组统一的 token：

```css
--transition-cubic-duration: 0.5s;
--transition-cubic-timing: cubic-bezier(0.65, 0, 0.35, 1);
```

确保整站交互节奏一致。

### 圆形扩散背景的实现

`background-color` 是标量属性，没有"从某个点扩散"的几何过渡能力。所以做法是：

- 元素本身加 `position: relative; isolation: isolate;`，建立独立堆叠上下文
- `::before` 绝对定位铺满，`z-index: -1` 沉到内容之下、但被父级 isolation 隔离
- 通过 `clip-path: circle(0%)` → `circle(100%)` 实现圆形扩散
- `border-radius: inherit` 保证圆角跟随父元素

`clip-path: circle(100%)` 在 CSS 规范中半径计算为 `sqrt(w²+h²)/sqrt(2)`，对任意宽高比都能完全覆盖到四角。

### 过渡哪些属性

`.transition-cubic` 内置以下属性的过渡：

- `scale`、`transform`
- `border-radius`、`border-color`
- `opacity`
- `box-shadow`
- `clip-path`（仅 `::before` 上，驱动背景扩散）

**特意没有 `background-color`** —— 背景过渡交给伪元素的 `clip-path` 完成。如果再把 `background-color` 加进 transition 列表，会和伪元素的圆形扩散冲突。

## 引入

类名通过 `@mui-verse/ui/verse.css` 全局注入，无需单独引入。

## 基础用法

### 1. 仅过渡（不带背景扩散）

不设置 `--transition-cubic-bg` 时，`::before` 保持透明，效果等同于一个统一节奏的 `transition`：

```tsx
<button className="transition-cubic rounded-2xl px-4 py-2 hover:scale-105">
  Hover me
</button>
```

### 2. 圆形扩散背景

通过 `--transition-cubic-bg` 变量传入目标背景色，hover 时从中心扩散，离开时收拢：

```tsx
<div
  className="transition-cubic rounded-2xl px-4 py-2 [--transition-cubic-bg:var(--mui-palette-primary-main)]"
>
  Hover me
</div>
```

> Tailwind v4 的 arbitrary property 语法 `[--var:value]` 直接在 class 里设置 CSS 变量，无需 inline style。

### 3. 配合 border

⚠️ **不要写 `hover:border`** —— 它会让 `border-width` 在 hover 时从 `0` 变 `1px`，引发布局跳动（"咯噔"一下），且 `border-style: none → solid` 浏览器不支持过渡。

正确写法是**始终保留 1px 透明 border**，hover 时只动 `border-color`：

```tsx
<div
  className="transition-cubic rounded-2xl border border-transparent px-4 py-2 hover:border-white [--transition-cubic-bg:var(--mui-palette-primary-main)]"
>
  Hover me
</div>
```

### 4. 配合 ring（无布局占用）

如果不想让 1px 占据布局空间，用 `ring` —— 基于 `box-shadow` 实现，完全脱离布局流：

```tsx
<div
  className="transition-cubic rounded-2xl px-4 py-2 ring-1 ring-transparent hover:ring-white [--transition-cubic-bg:var(--mui-palette-primary-main)]"
>
  Hover me
</div>
```

`box-shadow` 已在 transition 列表里，所以 ring 颜色变化会自动套用同一条曲线。

## API

### CSS 变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `--transition-cubic-duration` | `0.5s` | 过渡时长 |
| `--transition-cubic-timing` | `cubic-bezier(0.65, 0, 0.35, 1)` | 缓动曲线 |
| `--transition-cubic-bg` | `transparent` | 圆形扩散背景的目标颜色。不设置则不出现背景动效 |

需要单独调整某个元素的节奏时，直接覆盖变量：

```tsx
<div className="transition-cubic [--transition-cubic-duration:1s]">
  慢一点
</div>
```

## 注意事项

### Layer 优先级

`.transition-cubic` 定义在 `@layer components` 中。Tailwind 的 utility 类在 `@layer utilities`，优先级更高。

这意味着：

- ✅ **`hover:bg-primary-500` 会覆盖**伪元素的扩散背景（因为 `bg-*` 设在元素本身、不动伪元素），但**不会动画**——所以视觉上是"突变"的色块盖住扩散效果。**不要混用**。
- ✅ `transition-[xxx]`（utility）会**覆盖** `.transition-cubic` 的 `transition` 简写。同样不要混用。

### 隐含的副作用

`.transition-cubic` 会给元素加上：

- `position: relative` —— 一般无影响，但如果元素本来依赖默认 static 定位，注意 `z-index` 行为会启用。
- `isolation: isolate` —— 创建独立堆叠上下文，元素内部的 `z-index` 与外部隔离。

### 不适用场景

- 元素本身被设置了 `overflow: hidden` 但又依赖外部投影时，`::before` 不受影响（它在元素内部），但 ring/box-shadow 会被裁剪。
- inline 元素无法承载伪元素布局，需要 `inline-block` 或 `block`。

## 最佳实践

### ✅ 推荐

```tsx
// 用变量切换扩散色，配合 ring 做无布局占用的高亮
<button
  className="transition-cubic rounded-xl px-4 py-2 ring-1 ring-transparent hover:ring-primary [--transition-cubic-bg:var(--mui-palette-primary-main)]"
>
  Action
</button>
```

### ❌ 避免

```tsx
// 不要混用 hover:bg-* —— 会盖掉伪元素扩散
<div className="transition-cubic hover:bg-primary-500 ...">

// 不要混用 transition-[xxx] —— 会覆盖统一节奏
<div className="transition-cubic transition-[background-color] ...">

// 不要用 hover:border —— 引发布局跳动
<div className="transition-cubic hover:border ...">
```
